# 미션 1 요구사항 대조와 반영

대상 버전: 0.3.0. 비교 기준은 제공된 HD현대로보틱스 Mission 1 안내문 1–2쪽, 10월 4일 회의 정리의 본문 기준일 2026-10-05, Candidate Ranking을 유지하고 PPO를 후속 상위 행동 정책으로 검토한다는 추가 결정입니다. 기존 배포 기준 커밋은 `f69d88e97a0c6f887d32b98c30f45e8d8496f05a`입니다.

기존 구현은 공간·미래 성능·기본 안전 제약을 갖췄으나 다섯 평가 항목의 완전한 대응으로 보기는 어려웠습니다. 이번 버전은 평가 수치와 실행 검증 계약을 보완합니다. 실제 로봇 동작과 동역학 안정성은 외부 검증이 필요합니다.

## 담당 평가 항목

| 안내문 2쪽 항목 | 기존 상태 | 이번 반영 | 남은 범위 |
|---|---|---|---|
| 적재율·공간 활용도 | 6×6 공간 근사와 미래 추가 적재량 | 배치 전후 정확한 박스 체적률, 바닥 점유율, 높이, 예상 총 체적률 반환 | 공간 연결성과 잔여 footprint는 근사이며 최적해 보장 없음 |
| 패턴 생성·로봇 작업 예상시간 | `decision_ms`와 좌표 기반 작업시간 대용값 | 외부 후보 생성시간 + 평가시간 분리, 상태에 묶인 로봇 사이클 시간 수용·점수 반영, 소프트 계산 예산 | 실제 설비 사이클 시간 보정, 실시간 최악 지연 보장 |
| 무게중심·하중 분포 | CoG 여유와 최소 하중 여유 | 실제 m 단위 CoG, 박스별 상부 하중·허용치, 바닥 4분할 하중 지도 | 하중 지도는 바닥 박스 면적의 균등 압력 근사 |
| 지지면적·낙하·붕괴 가능성 | 단일 하부 박스의 완전 지지 마스크 | 접촉면적, 지지율, 지지하는 전체 상부 구조의 CoG 여유, 정적 강체 전도 대용 지표 | 마찰·재질·박스 변형·가속도가 없어 붕괴 확률은 `null`, 동역학은 `NOT_CHECKED` |
| 적재 순서 실행 가능성 | 현재 박스 1개의 packing 유효성, 로봇 검사 필요 표시 | 확인된 현재/preview 순서·선반 박스에 대한 순차 검증, 외부 IK·도달성·충돌·가반하중·파지 방향·접근 자세의 6개 검사, 거절 후보 재선정 | 실제 IK/경로/충돌 해석기는 외부 모듈에서 수행 |

현재 박스가 동일한 후보끼리는 체적률이 같습니다. 따라서 체적률을 중복 보상하기보다 남는 공간과 미래 적재량으로 위치를 비교하고 체적률은 KPI로 반환합니다. 지지면적은 현 코어에서 100% 지지를 요구하므로 안전 마스크로 작동합니다. 신규 설명 지표를 전부 신경망이 학습했다고 해석하지 않습니다.

## 전후 단계와의 연결

| 단계 | 입력·출력 연결 | 방어 동작 |
|---|---|---|
| ① 인식·모델링 → 평가 | m/kg/N, 팔레트 좌표, 측정 물성, SKU 수량, 확인된 배치와 지지 ID | 단위·방향·중복 ID 검증, 측정 오류 재측정, 배치·상부 하중 재구성 불일치 시 HOLD |
| ② 패턴 생성 → 평가 | 위치·회전 후보와 후보 생성시간. 참고 코드의 mm/grid 후보는 `adapters.py`로 변환 | 후보마다 packing 마스크 재검사, 후보 ID 중복 거절, 마스크 사유 반환 |
| 평가 → 로봇 계획 → 재평가 | 후보 순위·상태/위치 토큰 → 로봇 검사·예상시간 → `execution_mode=validated` | 실패 후보 제외, 누락·오래된 결과면 HOLD, EOAT를 합친 질량 사전 검사 |
| ④ 예외 처리 → 재계획 | 손상은 NG, 센서 실패는 재측정, 물성/팔레트 상태 수정 후 재요청 | 변경된 상태에서 과거 로봇 결과는 무효. 기존 박스 상태가 모순이면 먼저 정합성 복구 |
| ⑤ 시뮬레이션·표시 | 후보 순위·점수 기여도·물리 단위 KPI, 2D/등각 3D SVG, `scene_data()` | 표시용 예상 배치를 실제 적재 완료 상태로 갱신하지 않음 |

평가기와 Planner는 입력을 변경하거나 로봇에 명령을 보내지 않습니다. 제어기는 작업 성공 피드백 이후 `placed_boxes`, 하중, 재고, 선반을 갱신하고 다음 관측을 요청해야 합니다. 파지 실패 때 실행 예정 배치를 먼저 확정하면 안 됩니다. `state_version`과 `robot_scene_version`은 각각 상태 관리자와 로봇 장면 관리자가 갱신합니다.

팔레트 교체/부분 재배치 중에는 일반 적재를 중단합니다. 교체 중 정상 박스는 선반 여유가 있을 때 보관을 제안하고, 여유가 없으면 컨베이어 정지를 요청합니다. 교체 완료 직후 선반을 먼저 처리하려면 현재 컨베이어 투입을 멈추고 `current_box=null`로 선반 관측을 전달합니다. 실제 교체 동작·교체시간 최적화·부분 재배치 탐색은 이 평가기의 구현 범위가 아닙니다.

## 회의 결정과의 관계

직접 충돌하는 핵심 알고리즘 요구는 없습니다. 다음은 구현 범위와 우선순위의 차이입니다.

| 쟁점 | 적용 결정 |
|---|---|
| 안내문의 AI/강화학습 키워드 | PPO를 의무로 해석하지 않음. 기존 MLP Candidate Ranking → Top-K → Rollout 유지 |
| 실제 로봇 수행 가능한 순서 요구 vs 회의의 로봇 PoC 후순위 | 평가기 안에서 로봇 검증을 대신했다고 주장하지 않음. 별도 검증 계약과 미검증 실행 차단을 먼저 제공 |
| 안내문의 부분 재계획 vs 회의의 Partial Repacking 고급 확장 | 관측 변경 후 앞으로의 후보를 다시 계산하는 재계획은 구현. 이미 쌓인 박스를 옮기는 재배치는 보류 |
| 단순 안정성 가중합 | 최소 기준은 마스크, 목표 미달은 최소 안전 여유 우선, 목표 이상은 효율 우선 유지 |
| 참고 구현의 다중 지지·옆으로 눕힌 방향 | 이 코어는 단일 완전 지지와 upright yaw 0/90만 지원. 옆눕힘 2–5 방향은 자동 축소하지 않고 오류로 알림 |
| 정상 선반과 예외 보관 | 선반은 제한적 순서 조정용. 손상/측정 불확실 박스는 NG/Inspection 흐름으로 분리 |

`future.risk`는 샘플링된 미래 적재 성능의 하방 위험입니다. 물리적 붕괴 확률과 다릅니다. 이번 정적 안정성 지표도 실물 낙하 확률의 추정값이 아닙니다.

## 학습과 가중치

115개 신경망 입력과 미래 출력 4개, 배포 모델·학습 가중치 파일을 유지했습니다. 로봇 시간이 주어지면 6개 가중치 중 `handling`에 `min(1, cycle_seconds / 20)`을 사용합니다. 없으면 기존 기하 대용 시간을 사용하고 출처를 반환합니다. 신경망 입력의 시간 특징은 과거 학습 의미를 유지하기 위해 기하 대용값으로 고정합니다.

`teach → fit ranker`, `fit weights` 경로는 계속 사용할 수 있습니다. 안전 기준은 가중치 학습 대상에서 제외합니다. 기존 자동 가중치 탐색은 합성 환경의 적재 KPI로 선택하고 대용 작업시간을 Pareto 비교합니다. 실측 로봇 시간으로 가중치를 최적화했다는 의미는 아닙니다. 실제 시간 데이터 확보 후 실행 평가 환경에도 같은 시간 모델을 넣고 별도 validation 그룹에서 조정해야 합니다.
